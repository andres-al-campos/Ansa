# Ansa — iOS app

The SwiftUI client for Ansa. The server, the React app, and the MCP server live
in the parent directory; this directory is self-contained apart from the wire
format it shares with them.

`build.sh` is the entry point — prefer it over raw `xcodebuild`, and never build
by driving the Xcode GUI.

```
./build.sh              build for the iPhone, install, launch
./build.sh sim          the same, on a simulator, against a local wrangler
./build.sh test         run the AnsaCore suite (no device needed)
./build.sh wire         check the Swift op encoding against the server
./build.sh clean        drop the generated project and build output

./build.sh sim --no-auth   simulator build with no Clerk key
```

`--no-auth` exists so sync and lifecycle behaviour can be tested on the
simulator without signing in — a keyless build takes the unauthenticated path
straight to the outline. Refused for a device build, where it would look like it
worked while reading the dev stub's tree rather than the user's.

## Why the phone gets a Release build

Not about optimisation. A Debug build hardcodes `http://localhost:8787`, and on
the phone `localhost` is the phone — so a Debug build installed on a device talks
to nothing. The simulator shares the Mac's network, so it is the one place a
local wrangler is reachable, which is what `sim` is for. See `Sources/Config.swift`.

## Project layout

- **`project.yml` is the project.** The `.xcodeproj` is generated by xcodegen and
  gitignored. Edit `project.yml` and run `xcodegen generate` (build.sh does this
  for you). Never edit the `.xcodeproj` — the change is erased on the next build.
- **Sources are flat in `Sources/`**; `Info.plist` is at this directory's root,
  not inside `Sources/`.
- **`AnsaCore/` is a local SwiftPM package** holding the tree model and the ops —
  the Swift port of `shared/`. It has no UIKit or SwiftUI dependency, so
  `swift test` runs it without a simulator. Logic belongs there, not in a view.

## The model

- **`Tree` is a flat array** (`typealias Tree = [Node]`) with `parentId` pointers,
  not a nested structure. It matches the server's shape.
- **Edits are ops, never whole-tree writes.** Ops that create nodes carry their
  own ids and timestamps, minted on the device, so the server applies each one to
  exactly the node this client created.
- `./build.sh wire` checks the Swift encoding against the server's. Run it after
  touching anything in `AnsaCore/Sources/AnsaCore/Op*.swift`.

## Secrets

The Clerk **publishable** key is read from the macOS login Keychain (service
`ansa-clerk-publishable`) and baked into `Info.plist` at build time. It is public
by design — it ships in every client build — but it names a specific Clerk
instance, which is account state a fresh clone should not inherit. Not a `.env`
file, by preference.

The Clerk **secret** key lives only on the Worker, set with
`wrangler secret put CLERK_SECRET_KEY`. Never read it, never put it in a file,
never echo it into a shell.

`DEVELOPMENT_TEAM` lives in `Config.xcconfig`, gitignored, templated by
`Config.example.xcconfig`.

## This build.sh is deliberately not shared

`~/Projects/Code/ios-template` is the blueprint for new iOS apps, and
`walled_garden/sync-build-scripts.sh` keeps the three walled_garden copies
aligned. Ansa's is neither: it does Keychain key injection, builds Release for
the phone, and has `wire`. Fixes can be carried across by hand where they apply
— the device-id and install-retry logic is common to all of them — but do not
replace this file with a generated one.
